# IronMind Feature Planning Prompt

Use this prompt whenever planning a new feature, redesign, sprint, or improvement inside IronMind.

## Prompt

Act as:

1. Product Manager
2. Product Owner
3. UI/UX Designer
4. Software Engineer
5. Analyst
6. Behavioral Psychologist / Habit Coach
7. End User

Your job is to deeply think through the feature and create a practical execution plan.

You must:
- understand the purpose of the feature
- define why it matters
- evaluate whether it should exist, be changed, merged, delayed, or removed
- identify risks, edge cases, and UX concerns
- break big work into smaller, executable pieces
- recommend the best implementation order

## Output Format

## 1. Feature Name
- what is being planned

## 2. Goal
- what outcome this feature should create

## 3. Why It Matters
- why this feature matters to IronMind
- what user or product problem it solves

## 4. Persona-Based Thinking

### End User
- what the user needs
- what could confuse or frustrate them

### UI/UX Designer
- layout, hierarchy, interaction, visibility, emotional tone

### Product Manager
- feature priority
- placement
- whether it is daily-core or secondary

### Product Owner
- alignment with app vision
- whether the feature deserves long-term investment

### Software Engineer
- safe implementation path
- technical risks
- refactor or data model needs

### Analyst
- what should be measured
- what success looks like

### Behavioral Psychologist / Habit Coach
- whether this feature strengthens discipline, recovery, motivation, and habit formation

## 5. Risks
- list logic, product, UX, and technical risks

## 6. Recommended Product Direction
- best final shape of the feature

## 7. Phased Plan
Break the work into phases such as:
- data/model foundation
- UI implementation
- flow logic
- analytics
- polish

## 8. Smaller Work Pieces
Break the plan into small implementable tasks

## 9. Recommended Build Order
- what should be built first
- what should wait

## 10. What Should Not Be Changed
- list parts that should remain

## 11. Final Recommendation
- what to build now
- what to delay
- what to skip

## 12. Best Next Sprint
- give the sprint name
- explain what should start first

---

## Compact Version

Use this shorter form when needed:

- Goal
- Why it matters
- Persona concerns
- Risks
- Plan
- Small pieces
- Build order
- Next sprint

---

## Best Usage Notes

- Use this before building large features or redesigning important flows.
- Prefer phased planning over one giant implementation.
- Always separate:
  - what is critical
  - what is structural
  - what is optional polish
- For IronMind, always consider both:
  - product usefulness
  - behavior-shaping impact
