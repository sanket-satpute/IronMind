# IronMind Product Decision Prompt

Use this prompt whenever deciding whether a screen, feature, section, card, action, or flow should be kept, improved, moved, merged, simplified, delayed, or removed.

## Prompt

Act as:

1. Product Owner
2. Product Manager
3. UI/UX Designer
4. Software Engineer
5. Analyst
6. End User
7. Behavioral Psychologist / Habit Coach

Your task is to evaluate the thing being discussed and make a clear product decision.

You must determine:
- does it deserve to exist
- is it useful enough
- is it in the right place
- is it too important or not important enough
- should it stay, move, merge, shrink, or be removed
- what is the cost of keeping it vs changing it

## Output Format

## 1. What Is Being Decided
- name of screen / feature / section / component

## 2. Core Purpose
- what this thing is meant to do

## 3. Current Value
- what value it currently provides

## 4. Persona Review

### Product Owner
- does it fit IronMind’s long-term vision
- does it strengthen the brand and product identity

### Product Manager
- is it important enough
- is it in the right place
- is it daily-core, secondary, or optional

### UI/UX Designer
- does it help or clutter the screen
- does it improve hierarchy or hurt it
- should it be larger, smaller, hidden, grouped, moved, or redesigned

### Software Engineer
- what is the maintenance cost
- how risky is it to keep or change
- does it create technical complexity without enough value

### Analyst
- what evidence would justify keeping it
- what signals suggest it is low-value

### End User
- does it feel useful, confusing, noisy, motivating, or unnecessary

### Behavioral Psychologist / Habit Coach
- does it support discipline, recovery, motivation, or emotional balance
- does it create helpful pressure or unnecessary friction

## 5. Options
Evaluate these if relevant:
- Keep as is
- Improve
- Simplify
- Move
- Merge
- Delay
- Remove

## 6. Tradeoffs
- what is gained by changing it
- what is lost by changing it

## 7. Recommended Decision
Choose one final direction and explain why

## 8. Priority
Choose one:
- critical
- high
- medium
- low
- optional

## 9. Action Plan
If kept or changed, explain:
1. immediate step
2. next structural step
3. optional polish

## 10. Best Next Sprint
- give the sprint name
- explain what should happen first

---

## Compact Version

Use this shorter form when needed:

- Purpose
- Current value
- Problems
- Keep / move / merge / simplify / remove decision
- Why
- Next sprint

---

## Best Usage Notes

- Use this when a feature feels questionable, too noisy, too weak, too hidden, or too expensive to maintain.
- Be honest: not every feature should stay.
- For IronMind, always judge both:
  - product value
  - behavioral impact
