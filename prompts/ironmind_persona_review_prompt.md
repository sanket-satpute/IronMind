# IronMind Persona Review Prompt

Use this prompt whenever reviewing any screen, flow, feature, or product decision in IronMind.

## Prompt

Review this screen / feature using the full IronMind persona framework.

You must think through it as:

1. End User
2. UI/UX Designer
3. Product Manager
4. Product Owner
5. Software Engineer
6. Analyst
7. Behavioral Psychologist / Habit Coach

For each persona, explain:
- what is working
- what is weak
- what should be improved
- what should be removed, merged, moved, simplified, or emphasized

Then provide:

## 1. Feature / Screen Name
- what is being reviewed

## 2. Core Purpose
- what this screen or feature is supposed to do
- why it exists

## 3. End User Review
- clarity
- usability
- emotional reaction
- friction
- overload

## 4. UI/UX Review
- hierarchy
- spacing
- layout
- color usage
- typography
- interaction quality
- what should be primary / secondary / hidden

## 5. Product Manager Review
- is this feature important enough
- is it in the right place
- is it daily-core or secondary
- should it be promoted, collapsed, moved, merged, or removed

## 6. Product Owner Review
- does this align with IronMind's vision
- does it strengthen the product identity
- is it worth long-term investment

## 7. Software Engineer Review
- bugs
- logical risks
- edge cases
- technical debt
- maintainability
- refactor opportunities

## 8. Analyst Review
- what should be measured
- what assumptions need validation
- what success metrics matter
- what usage signals would prove this is valuable

## 9. Behavioral Psychologist / Habit Coach Review
- does this improve discipline
- does it create healthy pressure or unhealthy guilt
- does it support recovery, reward, and consistency
- what behavioral improvements should be made

## 10. Final Decision
Choose one:
- keep as is
- improve
- simplify
- move
- merge
- remove

## 11. Priority Level
Choose one:
- critical
- high
- medium
- low
- optional polish

## 12. Action Plan
Break the work into:
1. immediate fixes
2. structural improvements
3. optional polish

## 13. Best Next Sprint
- propose the next best sprint name
- explain what should be built first

---

## Compact Version

If a shorter review is needed, use this:

- End User: what feels good / bad?
- UI/UX: what should be clearer, smaller, bigger, calmer?
- Product Manager: should this stay here, move, merge, or shrink?
- Product Owner: does this fit the app vision?
- Software Engineer: bugs, risks, maintainability?
- Analyst: what should we measure?
- Behavior: does this improve discipline?

Then end with:
- Decision
- Priority
- Next Sprint

---

## Best Usage Notes

- Use this for any home screen, flow, onboarding step, challenge feature, social feature, or settings surface.
- For IronMind, do not review only as a UI. Always include behavior shaping and product fit.
- Prefer honest tradeoffs over praise.
- If something is good, say why.
- If something is weak, say whether it should be fixed, moved, merged, simplified, or removed.
